# Telegram Video Downloader

A production-oriented Telegram bot for downloading videos from YouTube, TikTok, and Instagram, then sending the result back to the user through Telegram.

The app is built around a fast webhook handler and a background Celery worker. The webhook only receives the Telegram update, rate-limits the user, records the request, queues work, and returns quickly. Heavy work such as yt-dlp extraction, downloading, probing, size checks, retries, and Telegram media upload runs in the worker.

## Features

- Telegram webhook bot powered by FastAPI and python-telegram-bot.
- Background video processing with Celery and RabbitMQ.
- Redis-backed per-user rate limiting.
- PostgreSQL download/user tracking through SQLAlchemy and Alembic.
- yt-dlp support for YouTube, TikTok, and Instagram.
- Platform-specific cookie selection for authenticated downloads.
- FFmpeg/ffprobe validation for video/audio streams.
- Quality fallback from 1080p to 720p to 480p.
- Safe client-facing errors with internal request references.

## Architecture

```text
Telegram
  |
  | POST /webhook/telegram
  v
FastAPI app (main.py)
  |
  v
Telegram application (bot.py)
  |
  v
Message handler (handlers/download.py)
  | - validates Telegram update shape
  | - checks Redis rate limit
  | - saves basic DB record
  | - queues Celery task
  v
RabbitMQ
  |
  v
Celery worker (services/worker.py)
  | - gets metadata when possible
  | - chooses safe quality
  | - downloads through yt-dlp
  | - probes media with ffprobe
  | - retries lower quality if needed
  | - sends media through Telegram API
  v
User receives video/audio
```

## Requirements

- Python 3.12 or newer
- Node.js 22.x, used by yt-dlp for some JavaScript challenges
- FFmpeg and ffprobe
- PostgreSQL
- Redis
- RabbitMQ

The project pins Python dependencies in `requirements.txt`.

## Environment Variables

Copy `.env.example` to `.env` for local development.

Required:

- `BOT_TOKEN`: Telegram bot token from BotFather.
- `WEBHOOK_URL`: Full Telegram webhook URL, for example `https://your-service.onrender.com/webhook/telegram`.
- `WEBHOOK_SECRET`: Random secret sent by Telegram in the webhook header.
- `DATABASE_URL`: SQLAlchemy async database URL, for example `postgresql+asyncpg://user:password@host:5432/db`.
- `DB_POOL_SIZE`: database pool size per app process. Default: `5`.
- `DB_MAX_OVERFLOW`: extra temporary database connections per app process. Default: `5`.
- `REDIS_HOST`: Redis URL, for example `redis://localhost:6379/0`.
- `RABBITMQ_HOST`: RabbitMQ broker URL, for example `pyamqp://guest:guest@localhost:5672//`.

Optional:

- `YOUTUBE_COOKIES_PATH`: Path to YouTube cookies in Netscape format.
- `TIKTOK_COOKIES_PATH`: Path to TikTok cookies in Netscape format.
- `INSTAGRAM_COOKIES_PATH`: Path to Instagram cookies in Netscape format.
- `YTDLP_COOKIES_PATH`: Generic fallback cookie path for other platforms.
- `APP_ENV`: `development` or `production`.
- `LIMIT`: rate-limit token capacity.
- `WINDOW_SEC`: currently reserved for configuration compatibility.

## Cookie Files

Cookies must be Netscape-format files exported from a browser session that can access the target content.

Recommended Render secret file paths:

```text
/etc/secrets/youtube_cookies.txt
/etc/secrets/tiktok_cookies.txt
/etc/secrets/instagram_cookies.txt
```

Set the matching environment variables:

```text
YOUTUBE_COOKIES_PATH=/etc/secrets/youtube_cookies.txt
TIKTOK_COOKIES_PATH=/etc/secrets/tiktok_cookies.txt
INSTAGRAM_COOKIES_PATH=/etc/secrets/instagram_cookies.txt
```

Do not commit cookies, `.env`, downloaded videos, logs, or generated bytecode.

## Local Setup

1. Create and activate a virtual environment.

```bash
python -m venv .venv
.venv\Scripts\activate
```

2. Install dependencies.

```bash
pip install -r requirements.txt
```

3. Install FFmpeg and make sure both commands work:

```bash
ffmpeg -version
ffprobe -version
```

4. Configure `.env`.

```bash
copy .env.example .env
```

5. Run database migrations.

```bash
alembic upgrade head
```

6. Start the Celery worker.

```bash
celery -A services.worker worker --loglevel=info --pool=solo
```

7. Start the web service.

```bash
uvicorn main:app --host 0.0.0.0 --port 10000
```

For a local Telegram webhook test, expose the app with a tunnel and set `WEBHOOK_URL` to the public tunnel URL plus `/webhook/telegram`.

### Tests

Install the development dependencies and run the deterministic test suite:

```bash
pip install -r requirements-dev.txt
pytest
```

The tests do not contact Telegram or supported media platforms.

## Render Deployment

Typical web service command:

```bash
uvicorn main:app --host 0.0.0.0 --port $PORT
```

Typical worker command:

```bash
celery -A services.worker worker --loglevel=info --pool=solo
```

Recommended services:

- One Render Web Service for FastAPI.
- One Render Background Worker for Celery.
- Managed PostgreSQL.
- Managed Redis.
- RabbitMQ provider such as CloudAMQP.

For 512 MB memory plans, keep worker concurrency conservative. `--pool=solo` or concurrency `1` is safest for media downloads.

## Operational Notes

- The webhook must return fast. Do not run yt-dlp, ffmpeg, or network-heavy validation in `handlers/download.py`.
- The worker owns all slow media work.
- Telegram upload limit is controlled by `MAX_TELEGRAM_FILE_SIZE` in `services/media_policy.py`.
- Long videos are rejected by `MEMORY_SAFE_MAX_DURATION_SECONDS` to protect memory.
- Celery task rate limiting is set in `services/worker.py`.
- Each queued download gets a short reference id that appears in both Telegram messages and worker logs.
- Production logs are JSON with request, platform, user, chat, quality, attempt, and duration fields where available.

## Troubleshooting

Low quality output:

- Check Render logs for selected size, codec, and target quality.
- Verify ffprobe is installed.
- Make sure yt-dlp can see higher-quality formats with the deployed cookies.

Instagram private or restricted reels:

- Refresh `INSTAGRAM_COOKIES_PATH` with cookies from an account that can view the exact reel.
- Check worker logs for cookie diagnostics. Do not expose cookie details to users.

YouTube formats missing:

- Make sure Node.js is available.
- Keep `remote_components` enabled in the yt-dlp options.
- Refresh YouTube cookies if age-restricted or login-gated videos fail.

Requests appear stuck:

- Check whether Celery is running.
- Check RabbitMQ connectivity.
- Check the task rate limit and worker concurrency.
- Look for the short reference id in worker logs.

## Code Map

- `main.py`: FastAPI app, Telegram webhook, startup/shutdown lifecycle.
- `bot.py`: Telegram application and handler registration.
- `handlers/download.py`: fast Telegram request handling and queueing.
- `services/worker.py`: Celery task orchestration.
- `services/downloader.py`: yt-dlp options, format selection, download validation.
- `services/video_info.py`: metadata extraction used by the worker.
- `services/media_probe.py`: ffprobe helpers.
- `services/media_policy.py`: file size, duration, and quality policy.
- `services/ytdlp_cookies.py`: platform-specific cookie selection and diagnostics.
- `services/telegram_sender.py`: synchronous Telegram API upload helpers.
- `services/rate_limit.py`: Redis token bucket.
- `services/user_service.py`: database user/download records.
- `database.py`, `model.py`, `alembic/`: database configuration and migrations.
